# 철마산역 — 전체 이벤트 설계

기준 시점: **중원력 732년 3월 상순 게임 시작**  
대상 지도: 철마산역  
목적: 철마산역의 장소별 상시 이벤트, 상시 랜덤 이벤트, 조건 이벤트를 실제 게임 데이터로 옮기기 위한 통합 설계서.

> 이 문서는 이벤트 설계 데이터의 기준안이다.
> 실제 챕터 대사 MD의 문법과는 별개이며, 대사 연출이 필요한 이벤트를 구현할 때는 최신 `시나리오_대본과_연출_편집매뉴얼.md`를 우선한다.
> 조건 이벤트는 플레이어가 개입하지 않아도 기간이 지나면 세계가 진행될 수 있어야 한다.

# 0. 공통 이벤트 규칙

## 이벤트 종류

### STATIC
장소에서 언제든 선택할 수 있는 상시 기능.

예:
- 휴식
- 수련
- 거래
- 소문 듣기
- 표행 확인
- 산채 관리

### RANDOM
장소 방문 또는 이동 시 확률적으로 발생하는 상시 랜덤 이벤트.

기본 권장 확률:
- 아무 일 없음: 65%
- 흔한 랜덤: 20%
- 보통 랜덤: 10%
- 드문 랜덤: 4%
- 희귀 이상: 1%

같은 이벤트의 연속 재발은 막는다.
반복 이벤트에는 개별 쿨다운을 설정한다.

### CONDITIONAL
날짜, 아이템, 인물, 관계, 능력, 세력, 점령, 플래그 등의 조건을 만족할 때만 발생하는 이벤트.

조건 종류 예시:

```text
date
period
item
character
relationship
faction
location_control
ability
flag
reputation
population
resource
```

# 1. 이벤트 데이터 공통 필드

각 이벤트는 최소 다음 정보를 가진다.

| 필드 | 의미 |
|---|---|
| `id` | 고유 이벤트 ID |
| `location` | 발생 장소 |
| `type` | STATIC / RANDOM / CONDITIONAL |
| `visibility` | always / condition / hidden |
| `conditions` | 발생 조건 목록 |
| `available_from` | 시작 시점 |
| `available_until` | 종료 시점. 영구면 null |
| `priority` | 이벤트 충돌 시 우선순위 |
| `repeatable` | 반복 가능 여부 |
| `cooldown_days` | 반복 가능 이벤트 쿨다운 |
| `choices` | 플레이어 선택지 |
| `results` | 즉시 결과 |
| `flags` | 후속 이벤트용 플래그 |
| `fail_result` | 기간 만료·실패 시 자동 결과 |
| `followups` | 후속 이벤트 ID |

권장 우선순위:

```text
100 긴급 기간 이벤트
90  메인/세력 사건
80  히로인·주요 인물 사건
70  아이템·능력·특수 조건 사건
60  일반 조건 사건
30  상시 랜덤
10  상시 기능
```

같은 장소에 여러 사건이 동시에 활성화된 경우 우선순위가 높은 사건을 먼저 처리한다.

# 18. 이벤트 충돌 처리

한 장소 방문 시 다음 순서로 처리한다.

```text
1. 이미 발생한 긴급 이벤트
2. 만료가 가까운 기간 이벤트
3. 메인·세력 조건 이벤트
4. 히로인·주요 NPC 조건 이벤트
5. 아이템·능력 특수 이벤트
6. 일반 조건 이벤트
7. 랜덤 이벤트 판정
8. 상시 기능 메뉴
```

한 번의 방문에 강제 이벤트를 여러 개 연속으로 터뜨리지 않는다.

기본적으로 강제 이벤트 1개가 끝나면 장소 메뉴로 돌아간다.
후속 이벤트가 즉시 이어져야 하는 경우에만 명시적으로 연결한다.

# 19. 기간 이벤트의 세계 자동 진행

기간 이벤트를 플레이어가 무시한 경우에도 사건은 멈추지 않는다.

예:

### 백운령 조난
- 1일차: 조난 발생
- 2일차: 부상자 증가
- 3일차 종료: 구조 실패 결과 확정

### 산불
- 발생 당일: 작은 산불
- 1일 방치: 확산
- 2일 방치: 대형 피해
- 해결하지 않으면 지역 자원량·주민 관계 변화

### 735년 토벌
플레이어가 태백총채 회의에 가지 않아도 각 산채는 자기 입장을 결정한다.

# 20. 히로인 이벤트와의 결합

마영란 전용 이벤트는 별도 문서:

`마영란_철마산역_히로인_이벤트_전체대본.md`

마영란 이벤트 역시 같은 이벤트 시스템에 등록하되 우선순위는 기본 80으로 한다.

일반 지역 이벤트가 마영란 동행 여부에 따라 변형될 수 있다.

예:

```text

+ 마영란 동행

DN-R02 밀수선
+ 마영란 동행
→ 위장 화물을 자동으로 의심
```

히로인 이벤트가 활성화됐다고 일반 이벤트를 완전히 막지는 않는다.
단, 같은 방문에서 히로인 핵심 이벤트와 일반 랜덤을 동시에 강제 발생시키지 않는다.

# 22. 구현 시 중요한 원칙

1. 랜덤 이벤트는 반복되는 잡음이 아니라 세계를 살아 있게 만드는 역할을 한다.
2. 조건 이벤트는 플레이어가 보지 않아도 시간이 지나면 진행될 수 있다.
3. 장소는 단순 버튼 집합이 아니라 시간이 지나면서 상태가 변한다.
4. 과거 선택은 후속 이벤트의 대사·선택지·NPC 반응에 반영한다.
5. 선량/악명 같은 단일 수치만으로 모든 결과를 처리하지 않는다.
6. 히로인은 별도의 연애 메뉴에 격리하지 않고 지역 이벤트 안에 섞는다.
7. 734년 이전에는 암천회·진루트의 정답을 노골적으로 노출하지 않는다.
8. 732년 3월에는 초반 생존과 지역 파악을 우선하며 대형 세계사건을 과도하게 발생시키지 않는다.
