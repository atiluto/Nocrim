# 녹림전생 — 대본·연출 편집 매뉴얼

기준: 2026-09-13 현재 프롤로그 구현. 다른 Chat에 시나리오 수정 작업을 맡길 때 함께 전달하는 문서다. 이 문서의 예제는 설명용이며, 작성만으로 게임에 반영되지 않는다.

## 1. 다른 Chat에 전달할 파일

**대사·배경·BGM은 챕터 MD에서, 인물 배치·이동은 `staging.json`에서, 날짜·위치는 `presentation.json`에서 수정한다.** 현재는 모든 연출을 챕터 MD 하나에 적는 방식이 아니다.

| 전달할 파일 | 용도 |
|---|---|
| 이 매뉴얼 | 실제 지원 문법과 제한 |
| 수정할 `P01_집이 필요했다.md` 등의 챕터 파일 | 대사, 화자, 배경, 음향, 화면 효과, 회상 |
| [staging.json](staging.json) | 인물 명단·역할·자리·이동·반응·사망 후 재등장 금지 |
| [presentation.json](presentation.json) | 상단 날짜·위치·아침/낮/밤과 전환 시점 |
| [음원 등록목록](../docs/audio/음원_등록목록.md) | 사용할 수 있는 음원 파일과 분위기 설명 |
| 필요한 `universe/` 설정 파일 | 인물과 사건의 설정 기준 |

가능하면 앞뒤 챕터도 함께 전달한다. 사망한 인물을 다음 장에서 다시 쓰거나 날짜가 거꾸로 가는 일을 막는 데 필요하다. 다른 Chat에서는 프로젝트의 로컬 경로를 직접 읽을 수 없으므로 파일을 첨부하거나 내용을 전달해야 한다.

MD만 전달한 경우에도 연출 제안은 받을 수 있다. 다만 이동 등을 `[추격자 중앙 이동]`처럼 대사에 넣지 말고 **대사 번호별 별도 수정 요청표**로 받아야 한다. 이 표를 실제 JSON으로 반영하는 작업은 따로 필요하다.

## 2. 대사 번호가 모든 파일을 연결한다

`### P06-006` 같은 번호를 **대사 ID**라고 한다. 같은 ID의 대사, 배치, 날짜 정보를 묶어 한 시점에 실행한다. 화면에 표시되는 `100 / 498` 같은 순번과는 다르다.

- 기존 ID는 수정·재번호 부여하지 않는다. 저장 위치와 다른 파일의 연출이 연결되어 있다.
- 실행 순서는 MD에 적힌 순서다. ID 문자열의 숫자 크기순으로 정렬하지 않는다.
- 문장 추가는 기존 내용을 먼저 보존한 뒤 고유 ID를 추가한다. 예: 기존 `P06-006` 다음에 아직 없는 `P06-006-02`. 중복 여부를 전체 대본에서 확인한다.
- ID를 삭제하면 `staging.json`의 `cues`, `presentation.json`의 `scene_status`, 사망 경계 `retired_at`에서 참조하는지 확인해야 한다. 저장 호환성도 별도 검토한다.
- 예전 자동 분할에 쓰던 `-PAGE02` 등의 ID를 원본 MD나 연출 파일에 직접 만들지 않는다. 현재는 한 ID가 한 화면이다. 중간에 클릭 간격이나 연출이 필요하면 별도 고유 ID의 대사로 나눈다. 기존 분할 페이지의 저장은 원본 대사 ID로 복원한다.
- `godot/data/prologue.json`은 변환 결과다. 직접 편집하지 않는다.

## 3. 챕터 MD의 정확한 형식

다음은 기존 P01 대사의 형식 예시다. 전체 파일을 이 블록 하나로 덮어쓰라는 뜻이 아니다.

```markdown
### P01-001
화자: 독백
배경: room
인물:
위치: right
음악: bgm/rain_on_the_wandering_cart.mp3
환경음:
효과음:
연출: fadein

대사:
나는 집이 필요했다. 대단한 집은 아니었다.
```

`### ID`, `항목: 값`, `대사:`의 철자와 반각 콜론을 유지한다. `대사:`는 단독 줄이고 실제 문장은 다음 줄부터 시작한다. 파일 첫 줄의 `# 프롤로그 1 — 집이 필요했다`가 챕터 제목이 된다.

**`대사:` 아래부터 다음 `### ID` 전까지는 전부 화면에 출력할 문장이다.** 그 사이에 설명, 연출 메모, JSON, HTML 주석을 끼워 넣지 않는다. 굵게 표시하는 Markdown이나 `[놀람]`도 게임 명령이 아니다.

| 항목 | 입력과 동작 | 다음 대사에 이어지는가? |
|---|---|---|
| `화자` | `독백`은 이름표 숨김. 그 외는 입력한 이름 표시 | 아니오. 각 대사에 적는다 |
| `배경` | 아래 표의 배경 키. 파일 경로를 직접 쓰지 않는다 | 아니오. 같은 배경도 반복해서 적는다 |
| `인물` | 옛 단일 인물 표기. 현재 화면 인물은 `staging.json` 기준 | 여기만 고쳐서는 인물이 바뀌지 않는다 |
| `위치` | 호환용 값. `left` 또는 `right` 유지 | 실제 이동은 `slot`으로 조절한다 |
| `음악` | BGM 파일 경로. 빈칸은 정지 | 유지하려면 다음 대사에도 같은 경로를 적는다 |
| `환경음` | 지속 환경음 경로. 빈칸은 정지 | 유지하려면 다음 대사에도 같은 경로를 적는다 |
| `효과음` | 해당 대사 시작에 한 번 재생 | 아니오 |
| `연출` | 아래 화면 효과 중 하나. 빈칸은 새 효과 없음 | 아니오 |
| `회상` | 선택 항목. `on` 시작, `off` 종료 | 빈칸/생략 시 유지. 챕터 시작은 off |
| `장면` | 선택 항목. 비어 있지 않으면 해당 대사 전에 전체 암전 전환 | 아니오. 문구는 화면에 표시하지 않는다 |

한 대사창은 1~2줄 정도로 짧게 쓴다. **글자 수에 따른 강제 줄바꿈과 자동 페이지 분할은 하지 않는다.** 한 ID가 한 화면이며, MD에 직접 넣은 줄바꿈을 유지한다. 대사 본문은 화면 좌우 15% 여백 안에서 이어진다(1280 기준 x=192, 폭=896). 한 줄이 이 폭을 넘으면 글꼴 크기에 맞춰 화면에서만 자동 줄바꿈한다. 긴 문단은 새 ID로 나누어 대사창 안에 들어가도록 편집한다.

아래 첫 예시는 기본 글자 크기에서 한 줄, 두 번째는 직접 줄바꿈한 두 줄로 표시된다.

```text
대사:
참 간단했다. 내 집은 내 것이 아니게 됐고, 모은 돈은 돌아오지 않았다.
```

```text
대사:
참 간단했다. 내 집은 내 것이 아니게 됐고,
모은 돈은 돌아오지 않았다.
```

독백은 `화자: 독백`으로 쓴다. `화자: 강산 독백`이나 `화자: 강산 · 독백`이라고 쓰면 그 문구가 이름표로 나온다. 강산이 실제로 말할 때는 `화자: 강산`을 사용한다. 현재 주인공은 1인칭이며 강산 스프라이트는 등록되어 있지 않다.

## 4. 배경 CG 선택

| 직접 사용할 키 | 장소·상황 | 기존 축약 키 |
|---|---|---|
| `black` | 검은 배경 | 동일 |
| `modern_room` | 현대 서울의 빈집 | P01의 `room` |
| `modern_forest` | 현대 한국의 나무 많은 산속 | P01의 `road` |
| `modern_rain` | 현대 산속의 비 오는 장면 | P01의 `rain` |
| `forest_path` | 무림 산속 산길 | P02 이후의 `road` |
| `solbaram_den` | 솔바람채 거처 | P02 이후의 `hut` |
| `village_overcast` | 흐린 마을 | P02 이후의 `village` |
| `maegol_stockade` | 매골채 | P02 이후의 `stockade` |
| `solbaram_night` | 솔바람채 야간 | P02 이후의 `camp` |

혼동을 줄이려면 직접 키를 사용한다. 특히 `road`는 P01과 나머지 장에서 다른 그림으로 바뀐다. 표에 없는 배경 이름을 새로 적는 것만으로 CG가 생성·등록되지는 않는다.

배경이 바뀌면 일반 진행 시 전체 암전 전환이 자동 발생한다. 배경만 바꿔도 상단 위치·날짜가 자동 추론되지는 않으므로 `presentation.json`도 함께 맞춘다. `배경: black`만으로 등장인물이 퇴장하지는 않는다. 검은 공간에 인물도 없어야 한다면 같은 ID에서 `stage: []`를 지정한다.

## 5. 날짜·장소·시간대와 암전

`presentation.json`의 **기존 `scene_status` 안**에 해당 ID 항목을 추가하거나 교체한다. 다음은 항목 하나의 예시이며 파일 전체가 아니다.

```json
{
  "P02-001": {
    "date": "무림 1일째",
    "location": "솔바람산 · 산길",
    "period": "아침"
  }
}
```

- `date`, `location`, `period` 세 항목을 모두 적는다. `period`는 **아침 / 낮 / 밤**만 지원한다.
- 상단에는 `무림 1일째 | 솔바람산 · 산길 | 아침`처럼 표시된다. 날짜는 표시용 문구이며 실제 게임 달력을 계산하는 명령이 아니다.
- 다음 상태 지정 전까지 계속 유지된다. 챕터가 바뀌어도 이 상태는 이어지므로 새 챕터 첫 대사의 날짜·위치를 확인한다.
- 새 상태 항목이 지정된 대사는 값이 앞과 같아도 암전 전환 지점이 된다. 모든 대사에 상태를 복사하지 않는다.
- 첫 대사의 초기 상태는 반드시 남긴다. 확정되지 않은 월·일은 임의로 설정하지 않고 기존 경과 일수를 유지한다.

날짜나 위치는 같지만 연출상 끊어야 할 때에는 MD의 `대사:` 위에 다음처럼 추가한다.

```text
장면: 잠시 후
```

이 문구는 전환을 표시하는 편집용 메모다. **화면 중앙에 “잠시 후”가 나오지 않는다.** 상단 표시가 바뀌어야 하면 `presentation.json`을 수정한다.

현재 전환 속도는 챕터 전환 약 1초 암전 → 0.8초 유지 → 0.9초 복귀, 날짜·장소·배경 전환 약 0.65초 암전 → 0.8초 유지 → 0.7초 복귀다. 화면 전체가 검어진 상태에서 내용이 바뀐다. 전환 중 진행 입력은 잠긴다. 대사마다 속도를 지정하는 기능은 없다.

암전 전환의 도착 대사에서는 인물을 검은 화면 뒤에서 즉시 배치한다. 그 대사에 등장 이동을 지정해도 화면 밖에서 걸어오는 과정은 보이지 않는다. **암전 뒤 등장 이동까지 보여주려면 다음 대사 ID에서 인물을 추가한다.** 도착 대사의 놀람·접근 반응과 효과음은 암전 복귀 후 실행된다.

## 6. 회상 시작과 종료

회상의 첫 대사에 `회상: on`, 현실로 돌아오는 첫 대사에 `회상: off`를 넣는다. 가운데 대사에는 생략해도 된다. 흐린 가장자리, 낮은 채도 느낌의 막, 회상 표식이 적용된다.

회상만으로 배경·인물·날짜가 바뀌지는 않는다. 필요한 CG와 무대 배치를 함께 수정한다. 현재 인물을 숨기려면 회상 시작 ID에 `stage: []`, 돌아온 ID에는 필요한 인물 전체 목록을 넣는다. 회상 앞뒤를 암전으로 구분하려면 `장면: 회상 시작` / `장면: 현재로 복귀`를 추가한다. 중앙 문구는 표시되지 않는다.

## 7. 등장인물 등록표와 역할 고정

다음은 `staging.json`의 `cast`에 등록된 인물이다. `actor`에는 한글 이름이나 이미지 파일명이 아닌 **인물 ID**를 쓴다. `화자`와 등록된 `speaker`가 정확히 같을 때 말하는 인물이 밝게 표시되고 듣는 인물은 조금 어두워진다.

| 인물 ID | 화자 이름 (`speaker`) | 이미지 키 | 용도 |
|---|---|---|---|
| `parksu` | 박달수 | `npc_bandit_scout` | 박달수 전용 |
| `mansik` | 조만식 | `npc_bandit_brute` | 조만식 전용 |
| `eokchil` | 최억칠 | `extra` | 최억칠 전용. 공용 엑스트라 아님 |
| `villager` | 마을 사람 | `npc_merchant` | 마을 상인 |
| `woodcutter` | 나무꾼 | `npc_villager` | 나무꾼 |
| `raider` | 매골채 산적 | `npc_bandit_raider` | 침입 산적 장혁 전용 |
| `lookout` | 빈 문자열 | `npc_bandit_patrol` | 일반 산적 |
| `pursuer` | 추격자 | `npc_bandit_patrol` | 추격하는 산적 |
| `patrol` | 빈 문자열 | `npc_bandit_patrol` | 순찰 산적 |
| `captive_bandit` | 붙잡힌 산적 | `npc_bandit_patrol` | 붙잡힌 산적 |
| `refugee` | 도망친 사람 | `npc_captive` | 도망친 민간인 |
| `prisoner` | 포로 | `npc_captive` | 민간 포로 |
| `mawung` | 마웅철 | `mawung` | 마웅철 전용 |
| `escort_guard` | 빈 문자열 | `npc_escort_guard` | 표국 무인 전용 |
| `escort_captain` | 진여명 | `npc_escort_captain` | 표국 장수 진여명 전용 |

빈 `speaker` 인물은 일반적인 이름 있는 대사에 자동 화자 반응을 하지 않는다. 반응시키려면 아래 `motions`로 직접 지정한다. 특정 인물의 발화 이름을 변경할 때는 MD와 `cast.speaker`를 함께 맞춘다. 인물 ID 자체는 유지한다.

최대 3명을 동시에 표시하며 **같은 이미지 두 장을 한 화면에 쓸 수 없다.** 예를 들어 `refugee`와 `prisoner`, 또는 `lookout`과 `pursuer`는 동시에 배치하지 못한다. 별개의 외모가 필요하면 새 이미지와 등록이 먼저 필요하다.

이미지별 역할은 `sprite_roles`, 한 인물 전용 여부는 `exclusive_sprites`가 제한한다. 이름만 바꿔 산적을 상인·표국 무인으로 재활용하지 않는다. 다음 사망 경계는 `retired_at`에 등록되어 있으며 **해당 ID부터** 전용 이미지 재등장이 금지된다.

| 인물 | 재등장 금지 시작 ID |
|---|---|
| 표국 무인 | `P02-023` |
| 최억칠 | `P02-025` |
| 박달수·조만식 | `P02-025-03` |
| 진여명 | `P02-026-04` |
| 장혁 | `P05-016-06` |

새 인물을 만들려면 기존 설정과 실제 이미지 파일을 확인한 뒤 `cast`, `sprite_roles`, 필요 시 전용·사망 정보를 함께 등록해야 한다. 다른 Chat이 이미지 키만 지어내거나 사망 제한을 지워 오류를 피하지 않도록 한다.

## 8. 자리, 화면 밖, 겹침

논리 화면 크기는 1280×720이다. `x`는 **그림 왼쪽 가장자리**의 위치이며 캐릭터 중심 좌표가 아니다. 그림 너비는 원본 비율에 따라 달라진다.

| `slot` | 현재 x | 새 등장 시 출발 방향 |
|---|---:|---|
| `left_back` | 5 | 왼쪽 밖 |
| `left` | 135 | 왼쪽 밖 |
| `center_left` | 300 | 왼쪽 밖 |
| `center` | 435 | 오른쪽 밖 |
| `center_right` | 610 | 오른쪽 밖 |
| `right` | 740 | 오른쪽 밖 |
| `right_back` | 830 | 오른쪽 밖 |

새 인물은 왼쪽 **x=-520**, 오른쪽 **x=1320**에서 목표 자리로 이동하면서 나타난다. 이것은 엔진이 사용하는 출발값이다. `slot: offscreen`이나 MD의 `위치: -520` 같은 문법은 없다. 퇴장은 목록에서 인물을 빼는 방식이다.

퇴장 방향은 현재 x가 430보다 작으면 왼쪽, 그 외에는 오른쪽이다. 처음 들어온 방향을 기억해 돌아가는 방식은 아니다. 중앙 `center`에서는 오른쪽으로 퇴장한다. 특정 방향이 필요하면 먼저 그 방향의 자리로 옮기는 별도 대사를 둔다.

평상시 세로 위치는 y=48, 그림 높이는 728로 고정한다. 그림 하단은 화면 아래까지 내려가며 원본 비율을 유지한다. 일반 이동은 가로로만 약 0.46초 진행한다. 크기 변화·상시 상하 흔들림·자리별 y 조정은 지원하지 않는다. 놀람·접근 도약만 잠깐 위아래로 움직인다.

`left_back`이라는 이름만으로 뒤에 그려지는 것은 아니다. **`stage` 목록의 앞 항목부터 뒤쪽에, 마지막 항목을 가장 앞쪽에 그린다.** 서로 가까운 자리를 고르고 목록 순서로 겹침을 조절한다. 인물끼리의 앞뒤이며 대화창 위로 올라오는 설정은 없다.

`slots`의 x와 `enter`를 편집하면 그 자리를 쓰는 모든 장면에 영향을 준다. 장면별 연출에는 기존 자리를 우선 사용한다. 고급 편집으로 자리를 추가할 때에도 허용 필드는 `x`, `enter`뿐이며 x는 -40~960, 방향은 `left`/`right`여야 한다. 화면 밖 출발값을 자리에 넣지 않는다.

## 9. 인물 배치·이동·퇴장 예제

아래 JSON들은 **`staging.json`의 기존 `cues` 안에 합칠 항목**이다. 파일 전체 교체용이 아니다. 같은 ID의 cue가 이미 있으면 그 안의 `stage`와 `motions`를 함께 검토하고 교체한다. 같은 키를 두 번 만들거나 JSON에 주석·끝 쉼표를 넣지 않는다.

`stage`는 그 시점부터 남을 **전체 인물 목록**이다. 새로 움직이는 한 명만 쓰면 나머지는 퇴장한다. `stage`를 생략하면 앞 배치가 유지되고, `stage: []`이면 모두 퇴장한다. 챕터 시작은 빈 무대이므로 필요한 인물을 다시 지정한다. 장소 변경은 같은 챕터의 배치를 자동으로 비우지 않는다.

### A. 왼쪽 도망자와 오른쪽 추격자 → 추격자가 중앙 접근

```json
{
  "P06-005-02": {
    "stage": [
      {"actor": "refugee", "slot": "left"},
      {"actor": "pursuer", "slot": "right"}
    ]
  },
  "P06-006": {
    "stage": [
      {"actor": "refugee", "slot": "left"},
      {"actor": "pursuer", "slot": "center"}
    ],
    "motions": [{"actor": "pursuer", "motion": "approach"}]
  }
}
```

두 번째 대사에서 도망자는 남아 있고 추격자만 중앙으로 이동한다. `approach`는 약 0.48초 뒤 짧게 뛰는 반응이다. **`approach` 자체가 중앙 이동 명령은 아니다.** 이동은 `stage`의 `slot` 변경으로 지정해야 한다. 이동만 필요하면 `motions`를 생략한다.

### B. 독백 중 특정 인물만 놀람

```json
{
  "P06-006": {
    "stage": [
      {"actor": "refugee", "slot": "left"},
      {"actor": "pursuer", "slot": "center"}
    ],
    "motions": [{"actor": "refugee", "motion": "jump"}]
  }
}
```

A의 같은 ID를 대체하는 다른 연출 예다. MD가 `화자: 독백`이어도 도망자가 반응한다. 해당 ID의 MD `연출:`은 비워 두면 된다. 앞 무대에 대상이 확실히 남아 있다면 `stage`를 생략하고 `motions`만 적어도 된다.

### C. 한 명 퇴장, 이후 모두 퇴장

```json
{
  "P06-017-03": {
    "stage": [{"actor": "refugee", "slot": "left"}]
  },
  "P06-024": {"stage": []}
}
```

첫 ID에서는 추격자가 빠지고 도망자만 남는다. 뒤 ID에서는 모두 퇴장한다. 암전 전환 지점에서는 퇴장 과정이 검은 화면에 가려질 수 있다.

### D. 두 인물을 겹쳐 배치

```json
{
  "P06-006": {
    "stage": [
      {"actor": "refugee", "slot": "center_left"},
      {"actor": "pursuer", "slot": "center"}
    ]
  }
}
```

가까운 두 자리를 쓰며 목록 마지막인 추격자를 앞에 그린다. 실제 겹치는 정도는 이미지의 너비와 여백에 따라 달라진다. 이 예도 A/B와 같은 ID를 쓰는 대안이므로 셋을 동시에 붙이지 않는다.

## 10. 반응 효과와 화면 효과의 차이

### 특정 캐릭터: `cues → motions`

| `motion` | 실제 동작 |
|---|---|
| `jump` | 즉시 20만큼 위로 0.12초 이동, 0.20초 동안 원위치로 복귀 |
| `approach` | 0.48초 기다렸다가 같은 도약. 자리 이동과 함께 사용 |
| `shake` | 해당 인물만 짧게 좌우 떨림. y는 움직이지 않음 |

대상은 해당 대사에서 무대에 있는 `actor`여야 한다. 여러 인물을 각각 반응시킬 수 있으나 같은 인물의 여러 동작을 나열해 순차 실행하는 기능은 아니다. 한 대사에서 한 인물에는 한 동작만 지정한다. 다음 대사로 넘어가면 이전 반응은 취소되고 원위치로 복귀한다. `nod`, `run`, `attack`, `fall`은 지원하지 않는다.

### MD의 `연출:`

| 값 | 실제 동작과 용도 |
|---|---|
| 빈칸 | 새 일회성 효과 없음 |
| `jump` | 현재 화자에 해당하는 화면 인물만 도약. 독백이나 강산처럼 대응 인물이 없으면 반응 없음 |
| `shake` | 배경만 짧게 흔들림. 인물 떨림은 위의 `motions` 사용 |
| `walk` | 배경만 작은 상하 흔들림으로 걷는 느낌. 캐릭터 이동 명령 아님 |
| `flash` | 대화창 위 장면 영역이 하얗게 번쩍이고 약 0.55초에 사라짐 |
| `fade` / `fadein` | 장면 영역의 검은 막이 약 0.55초에 사라짐. 현재 둘은 같은 밝아짐 효과 |
| `blackout` | 장면 영역이 약 0.35초에 검어짐. 다음 연출 갱신 때 막이 해제됨 |

한 `연출:`에는 값 하나만 적는다. `jump, shake`나 `flash 2초`는 지원하지 않는다. `blackout`은 대화창을 남기는 장면 영역 효과다. **날짜·장소·챕터를 구분할 때는 이 값 대신 5절의 전체 암전 전환을 사용한다.**

전체 암전의 도착 대사에 적힌 `flash`, `blackout`, `fade`, `fadein`은 중복 화면 효과를 막기 위해 실행하지 않는다. 번쩍임이 꼭 필요하면 전환 이후 별도 대사 ID에 둔다. MD `jump`와 대상별 `motions`가 같이 있으면 MD의 자동 화자 도약은 생략된다.

일회성 효과음·반응·화면 효과는 해당 대사 ID에 한 번 실행한다. 저장 불러오기와 빠른 넘기기에서는 반복 재생을 억제한다. 무대 배치·배경·회상·상단 상태는 저장 지점에서 복원된다.

## 11. BGM·환경음·효과음

경로 기준은 프로젝트의 `godot/assets/audio/`다. MD에는 이 앞부분을 빼고 정확한 파일명과 확장자를 적는다. 음원의 분위기 설명이나 생성 프롬프트를 경로 칸에 적으면 안 된다.

```text
음악: bgm/bgm_murim_survival.mp3
환경음: sfx/amb_mountain_morning_loop_01.mp3
효과음:
```

환경음 파일이 `sfx/` 폴더에 있어도 `환경음:`에 넣을 수 있다. 폴더명이 아닌 입력 항목이 재생 용도를 정한다.

| 실제 존재하는 경로 | 선택 참고 |
|---|---|
| `bgm/rain_on_the_wandering_cart.mp3` | 제공 목록상 비·피로·쓸쓸한 이동 정서. 현대 회상 등 |
| `bgm/bgm_murim_survival.mp3` | 현재 프롤로그 무림 구간에서 사용하는 BGM |
| `bgm/bgm_inn_afterhours.mp3` | 제공 목록상 긴 하루 뒤의 안정과 희미한 그리움 |
| `sfx/amb_mountain_morning_loop_01.mp3` | 현재 프롤로그 산속 환경음으로 사용 |
| `sfx/sfx_guard_spear_tap_01.wav` | 창을 두드리는 동작에 사용할 파일명 예 |
| `sfx/sfx_wooden_door_bolt_lock_01.wav` | 나무문 빗장 동작에 사용할 파일명 예 |

위 설명은 기존 목록과 사용처 기준이며 청취 검증을 뜻하지 않는다. 전체 선택지는 [음원 등록목록](../docs/audio/음원_등록목록.md)과 [catalog.json](../docs/audio/catalog.json)을 참조한다. catalog의 등록 당시 상태 문구만으로 현재 프롤로그의 재생 여부를 판단하지 않는다.

**음악과 환경음은 빈칸이 ‘앞 곡 유지’가 아니라 ‘정지’다.** 계속 들려야 하는 모든 대사에 동일한 경로를 적는다. 같은 경로를 연속해서 적으면 처음부터 재시작하지 않는다. 다른 경로를 적으면 곡이 바뀐다. 효과음은 실행할 대사에만 넣고 다음 대사에서는 비운다.

현재 한 대사에서 BGM 1개, 환경음 1개, 효과음 1개를 지정할 수 있다. 여러 효과음의 순차 재생, 재생 초 위치, 대사 중간 지연, 개별 음량, 반복 횟수, 대사별 페이드 시간을 입력하는 문법은 없다. 필요한 경우 별도 기능 구현을 요청한다.

## 12. 현재 지원하지 않는 것

- MD 안의 임의 명령: `[왼쪽 등장]`, `이동: center`, `놀람: on`, `BGM: 곡명` 등. 지원 항목 이름을 정확히 사용한다. 알 수 없는 메타 항목은 실행되지 않을 수 있으므로 검사 통과만 믿지 않는다.
- 표정 파일 자동 교체, 좌우 반전, 인물별 크기·y 변경, 비행·쓰러짐, 동작 지속 시간·속도·순서·지연의 자유 지정.
- 대사 없는 시간 대기 블록, 음성 립싱크, 대사 중간의 효과음 타이밍 지정.
- 날짜·장소 중앙 카드. 현재 UI는 암전과 좌상단 상태 표시 방식이다.
- 선택지·호감도 조건·루트 분기·전투 연결을 MD에 적어서 자동 구현하기. 현재는 11개 챕터의 선형 프롤로그다. 폴더를 추가한다고 분기가 생기지 않는다.

새 기능이 필요하면 다른 Chat의 결과에서 **‘추가 구현 필요’** 항목으로 분리한다. 작동하지 않는 문법을 완성된 게임 대본에 섞지 않는다.

## 13. 수정본 적용과 확인

1. 다른 Chat에서 수정한 챕터 MD를 원래 파일에 반영한다. 기존 ID와 수정하지 않은 내용은 보존한다.
2. 연출을 바꿨다면 해당 ID의 `cues`, `scene_status`도 원래 JSON에 합친다. 일부 항목 예제로 파일 전체를 덮어쓰지 않는다.
3. 새 ID·삭제 ID·사망 경계·인물 역할·배경·음원 경로를 확인한다. 같은 JSON 키 중복과 끝 쉼표를 없앤다.
4. 프로젝트 루트의 **`대사_적용.bat`**을 실행한다. 대본을 변환하고 생성 결과가 원본과 일치하는지 검사한다. 게임은 자동 실행하지 않는다.
5. 오류가 나오면 표시된 ID/파일을 고치고 다시 적용한다. 직접 합치기 어렵다면 수정 파일들과 함께 “이 대본과 연출을 게임에 반영해줘”라고 요청한다.

개발 환경에서의 동일한 절차는 `python tools/compile_scenario.py` 다음 `python tools/compile_scenario.py --check`다. `prepare_prologue.py`는 최초 각색 도구이므로 편집본 적용에 쓰지 않는다. 게임 화면 확인은 필요할 때 `play.bat`으로 별도로 한다. 정적 검사 성공은 실제 청취·화면 확인을 했다는 뜻이 아니다.

적용 전 점검:

- 한 대사창이 너무 길지 않고 감정·행동이 바뀌는 순간에 적절히 나뉘었는가?
- 독백은 이름표가 없는 `독백`인가?
- 날짜·장소 변경에 상단 상태와 암전 시점이 맞는가?
- 회상 종료에 `off`가 있으며 인물도 현실 배치로 돌아오는가?
- 대화 상대가 말하지 않는 동안에도 무대에 남아 있는가?
- 접근은 자리 변경과 반응을 구분했으며 y는 평상시 고정되는가?
- 사망한 인물이나 같은 이미지를 다른 역할로 재사용하지 않았는가?
- 음악·환경음의 빈칸 때문에 의도치 않게 소리가 끊기지 않는가?

## 14. 다른 Chat에 그대로 전달할 요청문

```text
첨부한 녹림전생 챕터 MD를 수정해줘. 함께 첨부한 ‘시나리오_대본과_연출_편집매뉴얼.md’의 현재 구현 문법을 따라줘.

기존 대사 ID와 사건·인물 설정을 보존하고, 한 화면 1~2줄 정도의 호흡으로 다듬어줘. 독백은 ‘화자: 독백’으로 써줘.
인물은 대화 중 무대에 함께 남기고, 필요한 이동·겹침·놀람·퇴장을 staging.json의 해당 ID cue로 작성해줘. stage는 화면에 남길 인물 전체 목록이야. 평상시 y와 크기는 바꾸지 마.
날짜·장소·아침/낮/밤 변경은 presentation.json에 반영하고 암전으로 구분해줘. 회상 시작과 종료도 명시해줘.
등록된 인물과 음원만 사용하고, NPC 역할·전용 이미지·사망 후 재등장 제한을 지켜줘. BGM과 환경음은 유지할 대사마다 같은 경로를 적어줘.

결과는 ① 수정한 챕터 MD ② 기존 staging.json의 cues 안에 합칠 ID별 항목 ③ 기존 presentation.json의 scene_status 안에 합칠 ID별 항목 ④ 변경 요약으로 구분해줘.
JSON 일부를 전체 파일이라고 표시하지 말고, 기존 항목을 삭제해야 할 경우 대상 ID와 이유를 따로 적어줘. 기존 파일을 전달받지 못했다면 추측으로 등록 정보를 만들지 말고 필요한 연출을 ID별 요청표로 정리해줘.
현재 지원하지 않는 효과나 새 이미지가 필요하면 ‘추가 구현 필요’로 분리하고, 대사 본문에 가짜 명령을 넣지 마. 다른 Chat에서 작성한 결과가 이미 게임에 적용되었다고 표현하지 마.
```

## 2026-09-14 실제 구현 보충 — 지역 사건

철마산역 실행 대본은 `scenario/events/chapters/<사건 ID>/`에 있다. 프롤로그와 동일한 한 ID = 한 화면 문법을 쓴다. 새 PAGE 번호를 자동 생성하지 않는다.

- 사건 발생 조건/선택/결과/다음 대사 묶음: `scenario/events/catalog.json`.
- 지역 인물 배치와 이동: `scenario/events/staging.json`.
- 지역 날짜/위치/시간대: `scenario/events/presentation.json`. `live:true`는 방문한 실제 게임 시각을 표시한다.
- 지역 MD 추가: `scenario/events/manifest.json`에 경로도 추가한다.
- `대사_적용.bat`은 프롤로그와 지역 사건을 모두 검사·적용한다.
- 상세 조작 규칙·스키마·저장·현재 미구현 목록: `docs/EVENT_SYSTEM.md`, `docs/EVENT_CATALOG.md`.

현재 무림 표기는 **중원력 732년 3월 상순**에서 시작한다. 일 단위 기한 처리를 위해 아침→낮→밤 뒤 다음 날로, 10일 뒤 다음 순으로 진행한다. 이 보충의 실제 구현 날짜 규칙이 앞의 구버전 순 진행 설명보다 우선한다. 원문 전체 문서를 수정한 경우에는 실행용 MD/조건과 비교하여 반영을 요청한다. 전체 원문을 자동 재추출하여 편집본을 덮어쓰지 않는다.

## 2026-09-14 실제 구현 보충 — 표정·배경·날씨

지역 `staging.json`에는 `ma_yeongran`(마영란), `jang_soyeon`(장소연), `ha_ryeonghwa`(하령화)가 등록되어 있다. 그림은 흰 배경이며 사용자가 직접 제거한다. 새로운 인물/표정 등록이 해당 인물의 전용 루트 구현을 뜻하지는 않는다.

- 각 cue에 `"expressions":{"ma_yeongran":"shy"}`처럼 표정을 쓸 수 있다. 무대에 있는 인물만 지정한다. 지원 표정은 해당 cast의 `expressions`에 실제 등록된 키만 사용한다.
- `stage`를 생략하면 기존 배치/표정을 유지한다. 새 `stage`를 적으면 기본 그림으로 재구성되므로 원하는 `expressions`도 함께 적는다. 기존 cue에 표정이 있으면 그 값도 검토한다.
- 마영란: `neutral/smile/surprised/angry/worried/shy`. 장소연: `neutral/smile/serious`. 하령화: `neutral/smile/worried`.
- 이동은 기존 `slot`, 반응은 기존 `jump/approach/shake`. 표정 변경은 위치·크기를 바꾸지 않는다.
- 새 배경 PNG 키는 presentation의 최상위 `backgrounds` 배열에 등록하고 MD의 `배경:`에서 사용한다. 사건 CG에 인물이 그려져 있으면 해당 구간 `stage: []`로 중복 입상을 숨긴다.
- presentation의 최상위 `weather` 객체에서 `"대사-ID":"rain"`, `"대사-ID":"snow"`, `"대사-ID":""`로 비·눈·해제를 지정한다. 대사 본문에 명령을 넣지 않는다. 같은 MD에서는 유지되고 다음 MD에서는 기본 해제되므로 독립 분기마다 필요하면 첫 ID에 적는다.
- 날씨는 대화창/인물 뒤에 표시되는 효과이며 날짜를 진행시키지 않는다. BGM/환경음은 기존처럼 유지할 대사마다 경로를 반복한다.

구체적인 JSON 예시, 생성된 파일 목록, 등장·퇴장·CG 연결, 배경 제거 후 교체 방법과 미제작 항목은 [히로인 미술·표정 편집 안내](../docs/HEROINE_ART.md)에 있다. 다른 Chat에는 이 매뉴얼과 해당 MD, staging, presentation 부분을 함께 전달한다.
